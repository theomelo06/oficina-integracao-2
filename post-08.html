Semana 8 — Código inicial do firmware

Com o desenvolvimento da aplicação encaminhado, começamos a organizar o código que vai rodar no ESP32. O firmware será responsável por receber os pedidos e coordenar os componentes físicos da máquina.

Organizando o código

O desenvolvimento está sendo feito em C++, usando o ambiente Arduino para compilar e gravar o programa na placa. Separamos as responsabilidades em arquivos .cpp e .hpp para facilitar os ajustes e evitar concentrar todo o funcionamento em um único arquivo.

A estrutura inicial contempla a conexão Wi-Fi, o recebimento de pedidos e os módulos ligados aos motores, à bomba, ao misturador e ao sensor de presença do copo. Essa organização permite desenvolver e testar cada parte aos poucos.

Conectando o ESP32 à rede

Uma das primeiras tarefas do firmware é conectar o ESP32 à rede Wi-Fi. Nesta versão inicial, o nome da rede e a senha são configurados no código. Depois da conexão, o endereço IP da placa é mostrado no monitor serial.

Esse endereço será usado pela API para localizar o ESP32. Para os testes locais, o computador que executa o back-end e a placa precisam estar em uma rede que permita a comunicação entre eles.

Recebendo a receita

A base da comunicação é um servidor HTTP executado no ESP32. A API envia uma requisição com o pedido em JSON, contendo as quantidades dos ingredientes e o sabor escolhido.

O firmware precisa ler o corpo dessa requisição, interpretar os campos e conferir se as informações necessárias estão presentes. Mesmo com a validação no back-end, a placa também deve verificar os dados antes de permitir qualquer acionamento.

Neste primeiro momento, o foco é receber corretamente a receita e devolver uma resposta para a API. Essa resposta confirma o recebimento do pedido; ela ainda não representa a conclusão do preparo da bebida.

Preparando o controle dos componentes

A próxima parte é ligar os dados recebidos às ações da máquina. A quantidade de pó precisará ser convertida em acionamento dos motores, enquanto o volume de água dependerá da calibração da bomba.

Também estamos planejando a sequência de preparo: verificar o copo, dosar os ingredientes, adicionar água e realizar a mistura. O sistema deverá impedir um novo pedido enquanto estiver ocupado e manter os atuadores desligados na inicialização.

Outro cuidado será evitar esperas longas que impeçam o firmware de atender à comunicação e verificar o sensor durante o funcionamento. Essa parte ganhará mais atenção conforme os módulos forem integrados.

Próximos passos

Vamos testar o envio de receitas da API para a placa, conferir as respostas e iniciar os testes individuais dos atuadores. A partir daí, poderemos integrar a sequência de preparo com os parâmetros obtidos na calibração.
